# 버그 추적

원인을 모르는 버그를 가설 여러 개로 나눠 동시에 확인하고, 원인을 찾은 뒤 하나만 고치는 절차예요.

## 구성

| 역할 | 페르소나 | 인원 | 맡는 일 |
|---|---|---|---|
| 확인 | `~/.maestro/personas/tester.md` | 가설 수만큼 | 고치지 않고 가설 하나를 확인 |
| 고치기 | `~/.maestro/personas/implementer.md` | 1 | 확인된 원인만, 재현 테스트 먼저 |

## 언제

- 재현은 되는데 원인이 불분명할 때
- 원인 후보가 여러 영역(프론트, 백엔드, 설정)에 걸쳐 있을 때

## 절차

1. **재현.** 재현 순서와 기대한 결과, 실제 결과를 적는다. 오류 메시지는 원문 그대로
2. **가설.** 원인 후보를 2–3개 적는다. 각각 "이게 원인이라면 …를 하면 …가 보여야 한다"는 확인 방법과 함께
3. **나눠 확인.** 가설마다 워커를 둔다. 고치지 말고 확인만 하게 한다
   ```
   maestro worktree create --name h1 --prompt "고치지 말고 확인만: 가설 <…>. 확인 방법 <…>. 맞는지 틀리는지와 근거"
   ```
4. **판정.** 결과를 모아 원인을 정한다. 다 틀렸으면 새 가설로 2번부터
5. **고치기.** 원인이 확인된 쪽 워커 하나에게만 고치게 한다. 재현 테스트를 먼저 쓰게 한다
6. **기록.** 문서 → RAG → 문제 해결 기록 형식으로 남긴다

## 주의

- 확인 단계에서 여러 워커가 동시에 고치기 시작하면 결과가 섞인다. 고치는 건 한 명만
