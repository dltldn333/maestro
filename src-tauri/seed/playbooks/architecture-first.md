# 아키텍처 먼저

구조를 먼저 설계해 캔버스에 그리고, 그 그림의 블록 단위로 구현을 나눠 맡기는 절차예요. 프롬프트 하나("○○ 만들어 줘")로 설계 → 그리기 → 구현 → 합치기까지 이어서 해요.

## 구성

| 역할 | 페르소나 | 인원 | 맡는 일 |
|---|---|---|---|
| 설계 | 마에스트로 자신 (아키텍트 관점: `~/.maestro/personas/architect.md`를 읽고 따른다) | - | 영역·블록·화살표와 블록별 명세 |
| 구현 | `~/.maestro/personas/implementer.md` (화면·스타일 블록은 `designer.md`) | 블록 수만큼 | 블록 하나를 구현 |
| 검토 | `~/.maestro/personas/reviewer.md` | 1 (선택) | 블록 사이 약속(화살표)이 지켜졌는지 확인 |

## 언제

- 새 기능이나 서비스, 페이지를 처음 만들 때
- 사용자가 캔버스에 구조를 그려 두고 "이거 만들어 줘"라고 할 때

## 그림 읽는 법

- **영역** = 경계(앱, 서버, 저장소, 도메인). 워커 하나가 영역을 넘나들며 고치지 않게 나눈다
- **블록** = 책임 하나, 워커 하나. 블록 내용(마크다운)이 그 작업의 명세다: 고칠 파일, 할 일, 지킬 것, 확인 방법
- **화살표** = 블록 사이 약속(호출, 데이터, 클래스 이름, 이벤트). 라벨이 그 이름이다

## 절차

1. **구조 받기.** `maestro selection`으로 사용자가 고른 블록·영역·화살표를 읽는다. 고른 게 있으면 3번으로
2. **설계하고 그리기.** 고른 게 없으면 직접 설계한다
   - 블록마다 **고칠 파일이 겹치지 않게** 나눈다(블록 3–5개면 충분). 같은 파일을 두 블록이 고치면 합칠 때 충돌난다
   - 화살표 라벨에 약속을 구체적으로 적는다(함수 이름, 클래스 이름, API 경로). 그 약속을 양쪽 블록 내용에도 똑같이 적는다
   - JSON 파일로 써서 캔버스에 그린다. 사용자가 그림을 보며 따라올 수 있다
   ```
   maestro draw --file .maestro-structure.json
   ```
   ```json
   {
     "areas": [{ "title": "웹" }],
     "blocks": [
       { "title": "마크업", "area": "웹", "body": "index.html만 수정. ..." },
       { "title": "스타일", "area": "웹", "body": "style.css만 수정. ..." }
     ],
     "arrows": [{ "from": "마크업", "to": "스타일", "label": "클래스 이름: hero, card" }]
   }
   ```
   - 사용자가 "확인받고 진행"을 원하지 않았다면 기다리지 말고 바로 3번으로 간다. 그린 구조를 한 줄로 알려 주기만 한다
3. **맡기기.** 블록마다 워커 하나. 명세 = 블록 내용 + 속한 영역 + 들어오고 나가는 화살표의 약속. 구성의 페르소나를 잇는다
   ```
   maestro worktree create --name <블록 이름> --prompt "<명세>"
   maestro ref add --to <블록 이름> --path ~/.maestro/personas/implementer.md
   ```
4. **합치기.** 워커가 끝날 때마다 `[maestro] 워커 … 완료` 메모가 온다. 결과를 `maestro read`로 확인하고, 쓰이는 쪽(화살표가 들어오는 블록)부터 기준 브랜치에 합친다. 합칠 때마다 실행해 확인한다
5. **보고.** 블록별로 끝남·남은 일을 표로 정리한다. 구현하며 구조가 바뀌었으면 `maestro draw`로 그림도 고친다(같은 이름은 고쳐 써진다)

## 주의

- 구조 파일(`.maestro-structure.json`)은 커밋하지 않아도 된다
- 그림에 없는 블록을 몰래 만들지 않는다. 필요하면 그림에 먼저 추가한다
