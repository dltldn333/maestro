# 계획 먼저, 구현은 나중

바로 고치지 않고, 먼저 조사와 계획을 세워 사용자 승인을 받은 뒤 구현하는 절차예요.

## 구성

| 역할 | 페르소나 | 인원 | 맡는 일 |
|---|---|---|---|
| 조사 | 없음 | 1 (선택) | 코드를 고치지 않고 조사만 |
| 계획 | `~/.maestro/personas/architect.md` | 1 (작으면 마에스트로가 직접) | 구조와 순서, 선택지 비교 |
| 기획 | `~/.maestro/personas/planner.md` | 1 (선택) | 목표·범위·완료 기준 |

## 언제

- 요청이 모호하거나 범위가 클 때
- 기존 구조를 바꾸는 일(아키텍처, 데이터 형식)
- 사용자가 "어떻게 할지 먼저 보여 줘"라고 할 때

## 절차

1. **조사.** 관련 코드를 읽는다. 크면 조사만 하는 워커를 둔다
   ```
   maestro worktree create --name survey --prompt "코드를 고치지 말고 조사만: <질문>. 관련 파일과 현재 동작을 정리해 줘"
   ```
2. **계획.** 아키텍트·기획자 관점으로 정리한다
   - 목표 한 줄과 하지 않을 것
   - 바꿀 파일과 순서
   - 선택지가 있으면 비교와 추천
   - 확인 방법
   결정할 가치가 있으면 PRD의 결정 기록 형식으로 남긴다
3. **승인.** 사용자에게 계획을 보이고 기다린다. 승인 전에는 구현하지 않는다
4. **구현.** 승인된 계획대로 "나눠서 구현"이나 "구현 → 리뷰 반복" 플레이북으로 넘긴다
5. **대조.** 끝나면 계획과 실제를 비교해 달라진 점을 보고한다
