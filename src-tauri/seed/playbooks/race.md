# 경쟁 실행

같은 과제를 워커 여러 명에게 동시에 맡기고, 결과를 비교해 가장 좋은 것을 고르는 절차예요.

## 구성

| 역할 | 페르소나 | 인원 | 맡는 일 |
|---|---|---|---|
| 경쟁 | `~/.maestro/personas/implementer.md` | 2–3 | 같은 명세를 각자 다른 방법·에이전트로 구현 |
| 비교 | `~/.maestro/personas/reviewer.md` | 1 (선택) | 브랜치들을 같은 기준으로 비교 |

## 언제

- 접근 방법이 여러 가지라 무엇이 나을지 모를 때
- 에이전트(Claude Code, Antigravity)나 모델끼리 비교하고 싶을 때
- 한 번에 잘 나와야 하는 중요한 변경

## 절차

1. 과제를 기능 명세 형식으로 한 번 정리한다(무엇을, 범위, 확인 방법). 모든 워커에게 똑같이 준다
2. 워커를 2–3명 만든다. 이름에 접근이나 에이전트를 드러낸다
   ```
   maestro worktree create --name race-a --prompt "<명세>"
   maestro worktree create --name race-b --agent antigravity --prompt "<명세>"
   ```
   서로 다른 방법을 시험하려면 명세 끝에 "이 방법으로: …"를 각자 다르게 붙인다
3. 기다린다. 워커가 끝나면 완료 메모가 내 입력창에 온다. 직접 확인하려면 `maestro read --to race-a`
4. 비교한다. 각 브랜치의 변경을 읽고 표로 정리한다
   | 워커 | 바꾼 파일 수 | 테스트 | 장점 | 문제 |
   |---|---|---|---|---|
5. 하나를 고르고 이유를 사용자에게 보고한다. 다른 워커의 좋은 부분이 있으면 고른 쪽에 옮겨 달라고 `maestro send`로 지시한다
6. 사용자가 승인하면 고른 브랜치를 기준 브랜치에 합친다

## 주의

- 명세가 다르면 비교가 안 된다. 같은 문장을 그대로 보낸다
- 진 워커의 워크트리는 사용자가 지운다(에이전트는 지우지 않는다)
