# 나눠서 구현

큰 기능을 겹치지 않는 조각으로 나눠 워커들이 동시에 만들고, 마에스트로가 순서대로 합치는 절차예요.

## 구성

| 역할 | 페르소나 | 인원 | 맡는 일 |
|---|---|---|---|
| 나누기 | `~/.maestro/personas/planner.md` | 1 (선택, 큰 일일 때) | 조각과 인터페이스 정리 |
| 구현 | `~/.maestro/personas/implementer.md` | 조각 수만큼 | 조각 하나씩 |
| 테스트 | `~/.maestro/personas/tester.md` | 1 (선택) | 합친 뒤 전체 확인 |

## 언제

- 한 명이 하기엔 크고, 서로 다른 파일이나 모듈로 나눌 수 있을 때
- 예: 백엔드 API / 프론트 화면 / 테스트·문서

## 절차

1. **나누기.** 기획자처럼 작업을 쪼갠다. 조각마다
   - 바꿀 파일(조각끼리 겹치지 않게)
   - 다른 조각과 맞춰야 할 인터페이스(함수 이름, 타입, API 모양)
   - 확인 방법
   인터페이스를 먼저 정해서 모든 조각 명세에 똑같이 적는다
2. **맡기기.** 조각마다 워커를 만든다. 역할이 있으면 페르소나를 잇는다
   ```
   maestro worktree create --name api --prompt "<조각 명세>"
   maestro ref add --to api --path ~/.maestro/personas/implementer.md
   ```
3. **지켜보기.** 완료 메모를 받으면 `maestro read --to <이름>`으로 결과를 확인한다. 막힌 워커에게는 `maestro send`로 답한다
4. **합치기.** 의존 순서대로 하나씩 기준 브랜치에 합친다(먼저 쓰이는 쪽부터). 합칠 때마다 빌드와 테스트
5. **마무리.** 전체를 한 번 실행해 확인하고, 사용자에게 조각별 결과와 남은 일을 보고한다

## 주의

- 두 워커가 같은 파일을 고치게 나누지 않는다. 피할 수 없으면 순서를 정해 하나가 끝난 뒤 다음 워커를 시작한다
- 인터페이스를 바꿔야 하면 모든 관련 워커에게 같이 알린다
