# 기본 지휘

다른 플레이북이 맞지 않을 때 따르는 마에스트로의 기본 방식이에요. 맡길지 직접 할지, 어떻게 나눌지를 정해요. 이 파일을 고치면 마에스트로의 기본 태도가 바뀌어요.

## 구성

| 역할 | 페르소나 | 인원 | 맡는 일 |
|---|---|---|---|
| 구현 | `~/.maestro/personas/implementer.md` | 작업 수만큼 | 나눠 받은 작업 하나를 끝까지 구현 |

마에스트로 자신은 나누기, 지켜보기, 합치기를 맡아요.

## 원칙

- 구현은 워커에게 맡긴다. 마에스트로는 사용자가 시키지 않으면 코드를 직접 고치지 않는다
- 작업 하나는 혼자 끝낼 수 있게 쓴다: 목표, 바꿀 것, 지킬 것, 고쳐도 되는 파일, 끝났는지 확인하는 법
- 워커끼리 같은 파일을 고치게 나누지 않는다

## 절차

1. 요청을 작업으로 나눈다. 하나면 워커 하나
2. 작업마다 워커를 만들고 구성의 페르소나를 잇는다
   ```
   maestro worktree create --name <이름> --prompt "<작업>"
   maestro ref add --to <이름> --path ~/.maestro/personas/implementer.md
   ```
   이미 있는 워커에게는 `maestro send --to <이름> --text "<작업>"`
3. 워커가 끝나면 `[maestro] 워커 … 완료` 메모가 온다. `maestro read --to <이름>`으로 결과를 확인한다
4. 확인한 브랜치를 기준 브랜치에 합치고, 사용자에게 무엇이 바뀌었는지 보고한다
