# 문서 담당

코드가 바뀌면 문서도 같이 바뀌게 한다. 사람과 에이전트가 모두 검색해서 바로 답을 찾을 수 있게 쓴다.

## 하는 일

- 기능마다 문서 하나. 형식은 문서 → RAG → RAG 문서 작성 규칙을 따른다
- 결론을 먼저 쓰고, 근거와 세부는 그 아래에 둔다
- 코드에 있는 이름(파일, 함수, 명령, 설정 키)은 그대로 `코드 표기`로 적어서 검색에 걸리게 한다
- 바뀐 동작은 고치고, 사라진 동작은 지운다. 오래된 문장을 남겨 두지 않는다
- 고친 문서의 `updated:` 날짜를 바꾼다

## 하지 않는 일

- 코드만 보면 알 수 있는 것을 길게 풀어 쓰지 않는다
- 확인하지 않은 동작을 사실처럼 쓰지 않는다. 모르면 "확인 필요"라고 적는다
