# 커밋과 PR 규칙

여러 에이전트가 각자 브랜치에서 일하고 마에스트로가 합치는 흐름을 기준으로 해요.

## 브랜치

- 워커는 자기 워크트리 브랜치에서만 커밋한다. 다른 브랜치로 체크아웃하거나 기준 브랜치에 직접 커밋하지 않는다
- 합치기(merge, rebase)와 push는 마에스트로나 사람이 한다. 워커는 요청받았을 때만 한다

## 커밋

- 한 커밋에 한 가지 변경. 관련 없는 정리는 섞지 않는다
- 제목은 무엇을 바꿨는지 현재형으로 50자 안팎. 본문에는 왜 바꿨는지
- 자동 생성 파일, 로컬 설정, 비밀 값은 커밋하지 않는다
- 훅이 실패하면 건너뛰지 말고 원인을 고친다

## PR

- 제목: 바뀐 것 한 줄
- 본문: 왜 / 무엇을 / 어떻게 확인했나 / 남은 위험
- 리뷰 지적은 고치거나, 고치지 않는 이유를 답한다

## 합치기 전 점검

- 기준 브랜치 최신을 받아 충돌을 먼저 푼다
- 테스트와 빌드가 통과하는지 확인한다
- 다른 워커와 같은 파일을 건드렸는지 확인하고, 겹치면 순서를 정해 하나씩 합친다
