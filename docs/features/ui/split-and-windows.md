# 워크스페이스

## 요약

모든 창의 화면 구성(어떤 창이 있고, 각 창이 탭 묶음을 어떻게 나눠 보여 주는지, 묶음마다 어떤 탭이 열렸는지)은 백엔드(Rust)가 한 벌만 가지고 있어요. 창은 그걸 보여 주는 화면일 뿐이에요. 탭이나 묶음을 다른 묶음·다른 창으로 옮기는 건 그 상태를 한 번 바꾸는 일이라, 데이터를 포장해서 넘기지 않아요. 새 창은 미리 띄워 둔 숨은 창을 꺼내 쓰기 때문에 바로 떠요. 분할은 창의 것이지 프로젝트의 것이 아니고, 묶음마다 자기 프로젝트를 하나 보여 줘요.

## 동작

**분할 만들기**
- **탭 끌기**
  - 탭을 묶음 위로 끌면 놓일 자리가 반투명하게 미리 보여요.
  - 가장자리 1/4(왼쪽·오른쪽·위·아래)에 놓으면 그쪽으로 새 묶음이 갈라져요.
  - 가운데나 탭 줄에 놓으면 그 묶음으로 들어가요. 다른 프로젝트의 묶음이면 오른쪽에 새로 갈라져요.
  - 탭이 빠져서 빈 묶음은 닫혀요.
- **프로젝트 탭 끌기:** 그 묶음 전체(하위 탭 모두)가 같은 규칙으로 옮겨져요. 같은 프로젝트 묶음의 가운데에 놓으면 탭이 합쳐져요.
- **사이드바에서 프로젝트 더블클릭:** 지금 묶음 오른쪽에 분할로 열려요. 이미 보이고 있으면 그 묶음으로 가요.
- **분할 버튼(▯▯):** 지금 탭을 복사해서 오른쪽에 하나 더 보여 줘요.
- **탭 오른쪽 클릭:** 오른쪽으로 분할, 아래로 분할, 새 창으로 열기, 탭 고정, 닫기
- 같은 방향 분할은 한 줄로 합쳐져요. 묶음 크기는 똑같이 나눠요.

**어느 묶음에 열리나**
- 묶음 안 어디든 누르면 그 묶음이 포커스를 받아요. 강조색 선은 포커스된 묶음의 열린 탭에만 보여요.
- 사이드바에서 프로젝트를 클릭하면, 그 프로젝트를 보이는 묶음으로 가요. 없으면 포커스된 묶음이 그 프로젝트로 바뀌고, 원래 탭은 기억해 뒀다가 돌아오면 되살려요.
- 사이드바의 워크트리, 파일 트리의 파일도 "그 프로젝트의 묶음"에 열려요.
- 사이드바 선택 표시, 오른쪽 패널, 뒤로/앞으로는 그 창에서 포커스된 묶음을 따라가요.

**새 창**
- 탭이나 프로젝트 탭을 창 밖(어떤 창도 받지 않은 곳)에 놓으면, 놓은 자리에 새 창이 바로 떠요.
- 탭 줄의 ↗ 버튼은 묶음 전체를, 오른쪽 클릭 → "새 창으로 열기"는 탭 하나를 새 창으로 보내요.
- 새 창에는 사이드바 없이 탭 줄과 화면만 있고, 그 안에서도 분할할 수 있어요.
- 창 사이에서 탭과 묶음을 끌어 옮길 수 있어요. 저장 안 한 편집도 따라가요.
- "메인 창으로"를 누르면 모든 묶음이 메인 창 분할로 돌아가요.
- 새 창은 보여 줄 게 없어지면(마지막 탭이 빠지거나, 메인으로 돌아가면) 저절로 닫혀요. ×로 닫으면 그 탭들은 사라져요.
- 메인 창을 닫으면 앱이 끝나요.

## 구현

**백엔드**(workspace.rs)
- `Workspace { state: (Value, version), drafts, pool }`
- 상태 모양: `{ windows: { <창 이름>: { layout, focus } }, groups: { <id>: Group }, parked: { <루트>: { tabs, path, editor } } }`
- 명령
  - `ws_get`: 지금 상태와 버전
  - `ws_commit(state, base)`: `base`가 지금 버전과 같을 때만 받아요. 다르면 거절하고 최신 상태를 돌려줘요. 받으면 버전을 올리고 모든 창에 `workspace://state`로 보내요.
  - `ws_draft_set` / `ws_draft_get`: 파일별 저장 안 한 편집이에요. 어느 창의 편집기든 같은 걸 봐요.
  - 창 예열
    - 시작 3초 뒤에 숨은 창 하나를 띄워 둬요(`warm_later`). 그 창은 페이지를 다 불러오면 `ws_window_ready`로 알려요.
    - `ws_take_window`: 예열된 창 이름을 주고, 다음 예열 창을 새로 띄워요. 예열된 게 없으면 새로 만들어요(그때는 로딩이 보여요).
    - `ws_show_window(label, x?, y?)`: 그 자리에 보여 주고 포커스해요.
- 창이 닫히면(`WindowEvent::Destroyed`) 그 창과, 그 창만 보여 주던 묶음을 상태에서 지워요(`drop_window`). 테스트: `closing_a_window_drops_only_its_groups`

**프런트엔드 동기화**(store.ts)
- 창마다 "백엔드가 확인한 상태(`confirmed`)" 위에 "아직 커밋 안 된 자기 변경들(`queue`)"을 얹은 걸 보여 줘요(`render`). 그래서 누르자마자 반응해요.
- 변경은 순수 함수(`(ws) => ws`)예요. 새 id는 함수 밖에서 미리 만들어요.
  - 하나씩 `ws_commit`해요. 다른 창이 먼저 바꿔서 거절되면, 같은 함수를 최신 상태에 다시 적용해요(낙관적 동시성).
  - 그래서 두 창이 서로 덮어쓰지 않아요.
- 커밋 중에 온 다른 창의 방송은 커밋이 끝난 뒤 반영해요(`latest`). 같은 변경이 두 번 적용돼 보이는 걸 막아요.
- 이 창의 화면 값(`layout`, `focus`, `groups`, `activeRoot`, `selectedPath`, `editor`)은 `ws.windows[ME]`에서 계산해요. `ME`는 창 이름이고, 메인은 `"main"`이에요.
- 핵심 규칙(순수 함수)
  - `routeTo`: 프로젝트의 묶음을 찾거나, 포커스된 묶음을 그 프로젝트로 바꿔요. 원래 탭은 `parked`에 보관해요.
  - `detach` / `removeGroup`: 묶음을 빼요. 빈 새 창은 상태에서 지워져서 닫히고, 메인은 빈 묶음을 하나 새로 받아요.
  - `dropTabWS` / `moveGroupWS`: 탭·묶음 놓기예요. 출발 묶음이 어느 창에 있든 같은 함수예요.
  - `leaveTab`, `closesWhenEmpty`
- 메인 창은 처음 연결할 때 자기 항목(`windows.main`)이 없으면 만들어요(`connect`).

**배치**(layout.ts): `insertAt`, `without`, `leaves`. 개발 빌드에서 자체 점검이 돌아요.

**화면**(Workspace.tsx, StageTabs.tsx)
- `Workspace` → `LayoutView`(재귀) → `GroupView`. 묶음마다 `ReactFlowProvider`가 따로 있어요.
- 끌기 데이터(`application/x-maestro-tab`)에는 id만 실어요.
  - 탭: `{ tab, root, from }`
  - 프로젝트 탭: `{ group }`
  - 받은 쪽은 `dropOn`으로 스토어에 넘겨요. 다른 창에서 온 것도 똑같이 처리돼요. 상태가 공유되니까요.
- 놓을 자리
  - 묶음에 끌기가 들어오면 `.drop-layer`가 깔려요. 캔버스·터미널·편집기가 드래그를 삼키지 않게 하려는 거예요.
  - `zoneAt`(가장자리 1/4)으로 영역을 정하고 `.drop-preview`로 보여 줘요.
- 창 밖에 놓기: `dragend`에서 `dropEffect === "none"`이고 창 밖이면 `popOutTab` / `popOutGroup(at)`을 불러요.
- `WorkspaceWindow`(`?ws=1`)
  - 숨은 채로 연결과 저장소 읽기를 마친 뒤 `ws_window_ready`를 보내요.
  - 자기 항목이 생기면 그려요. 항목이 있다가 없어지면 스스로 닫아요.
- 편집기의 저장 안 한 내용은 300ms 묶어서 `ws_draft_set`으로 보내요.
  - 탭이 다른 곳으로 옮겨져 편집기가 내려갈 때는 남은 입력을 바로 보내요.
  - 탭을 닫으면 지워요.
  - 새로 뜬 편집기는 `ws_draft_get`으로 이어받아요.

**자리 비움:** 창마다 보이는 프로젝트를 `set_away`로 알리고, 백엔드가 합쳐서 판단해요. → [자리 비움](../agents/away-stop.md)

## 제약과 알려진 문제

- 묶음 크기를 끌어서 바꿀 수 없어요.
- 워크스페이스 상태는 메모리에만 있어서, 앱을 다시 켜면 분할과 새 창은 사라져요. 마지막에 닫은 프로젝트의 탭과 마지막 위치는 남아요.
- 창 밖에 놓은 위치 계산과 창 사이 끌기는 WebView2의 드래그 동작에 기대요. 화면에서 확인하지 않았어요.
- 탭을 끄는 순간까지 300ms 안쪽의 입력은 다른 창에 늦게 도착할 수 있어요.
- 같은 파일을 두 묶음에서 동시에 고치면 실시간으로 맞춰지지 않아요.

## 결정 기록

- **처음 방식과 문제:** 창마다 상태를 따로 두고 localStorage와 이벤트로 넘겼어요. 그랬더니 새 창이 느렸고(웹뷰를 띄워 앱 전체를 새로 불러옴), 옮길 때마다 데이터를 포장해야 했어요. 그래서 "상태는 백엔드 한 곳, 창은 보여 주기만"으로 다시 짰어요.
- **규칙을 JS에 둔 이유:** 탭 규칙(미리보기, 이웃 탭, 분할 합치기)은 이미 TS에 있었어요. Rust로 옮기면 같은 규칙을 두 번 쓰게 돼요. 그래서 백엔드는 "한 벌의 상태 + 버전 확인 + 방송 + 창 관리"만 맡고, 규칙은 순수 함수로 두어 거절되면 다시 적용해요.
- **창 예열:** 웹뷰가 뜨는 비용은 피할 수 없어서, 미리 띄워 두고 꺼낼 때 보여 주기만 해요.
- **분할 단위:** "분할의 루트는 프로젝트지만 분할 자체는 프로젝트에 종속되지 않는다"는 요구에 따라, 배치는 창 단위이고 묶음 하나가 프로젝트 하나를 보여 줘요.
