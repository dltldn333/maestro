# 가운데 화면 탭

## 요약

가운데 화면(스테이지) 위에 탭 줄이 있어요. 첫 탭은 항상 프로젝트이고, 그 뒤로 워크트리와 파일이 붙어요. VS Code처럼 한 번 클릭하면 "미리보기 탭"(기울임꼴)으로 열리고, 다음 클릭이 그 자리를 다시 써서 탭이 마구 쌓이지 않아요. 편집하거나, 메시지를 보내거나, 더블클릭하면 탭이 고정돼요. 탭 줄 오른쪽 끝의 ‹ › 로 다녀온 곳을 뒤로/앞으로 오가요.

## 동작

**탭 종류**
- **프로젝트 탭(첫 탭):** 폴더 아이콘과 저장소 이름이 강조색 글자와 옅은 강조색 바탕으로 보여서 다른 탭과 구분돼요.
  - ×(또는 휠 클릭)로 닫으면 그 묶음이 탭들과 함께 사라져요(메인 창의 마지막 묶음이면 프로젝트 없이 남아요). 탭들은 기억해 뒀다가 그 프로젝트를 다시 열면 닫기 전 그대로 되살려요. 마지막에 닫은 프로젝트 하나는 앱을 다시 켜도 기억해요(localStorage `maestro.lastClosedProject`).
  - 저장하지 않은 파일이 있을 때만 확인을 물어요(그 편집은 사라져요).
  - 끌면 그 묶음 전체가 옮겨져요(분할·합치기·창 밖 새 창). → [워크스페이스](split-and-windows.md)
- **워크트리 탭:** 상태 점, 에이전트 로고, 이름이 보여요.
- **파일 탭:** 파일 아이콘과 이름이 보이고, 변경 비교면 "비교"가 붙어요.
- 탭은 프로젝트마다 따로예요.

**미리보기 탭(VS Code 방식)**
| 하는 일 | 결과 |
|---|---|
| 파일 트리·변경사항에서 파일 한 번 클릭 | 미리보기 탭으로 열려요 |
| 사이드바에서 워크트리 한 번 클릭 | 미리보기 탭으로 열려요 (더블클릭하면 고정 탭) |
| 다음 것을 또 한 번 클릭 | 새 탭 없이 미리보기 탭 자리가 바뀌어요(미리보기 탭은 늘 하나) |
| 파일 더블클릭, 파일 편집 | 그 파일 탭이 고정돼요 |
| 캔버스에서 카드 더블클릭, "♛ 마에스트로 캔버스" 버튼 | 고정 탭으로 열려요 |
| 워크트리 채팅에서 메시지 보내기 | 그 워크트리 탭이 고정돼요 |
| 탭 더블클릭 | 언제든 고정돼요 |
| 열린 화면(캔버스, 에이전트, 편집기) 안 아무 데나 더블클릭 | 지금 탭이 고정돼요 |
- 미리보기 탭은 이름이 기울임꼴이고, 마우스를 올리면 "더블클릭하면 탭을 고정해요"가 보여요.
- 이미 열린 것을 다시 열면 새로 만들지 않고 그 탭으로 가요. 고정된 탭은 미리보기로 돌아가지 않아요.

**뒤로 / 앞으로**
- 탭 줄 오른쪽 끝의 ‹(뒤로) ›(앞으로) 버튼이에요. 갈 곳이 없으면 흐리게 꺼져요.
- 탭을 옮기거나, 프로젝트를 바꾸거나, 파일을 열 때마다 기록돼요(최대 50개). 뒤로 간 상태에서 새 곳으로 가면 앞쪽 기록은 지워져요(브라우저와 같아요).
- 그 사이 닫혔거나 다른 미리보기로 바뀐 탭으로 돌아가면, 그 탭이 미리보기로 다시 열려요.
- 프로젝트가 목록에서 빠졌거나 워크트리가 폐기된 기록은 건너뛰어요.

**닫기**
- ×는 마우스를 올리거나 열린 탭에서 보여요. 휠(가운데 버튼) 클릭으로도 닫혀요.
- 저장 안 한 파일은 × 자리에 ●가 보이고, 닫을 때 확인을 물어요.
- 열린 탭을 닫으면 바로 왼쪽 탭(없으면 오른쪽, 그것도 없으면 프로젝트)으로 가요.
- 워크트리를 폐기하면 그 워크트리 탭과 그 안의 파일 탭이 함께 닫혀요.

**순서 바꾸기**
- 탭을 같은 탭 줄 위에서 좌우로 끌면 순서가 바뀌어요. 놓일 자리에 강조색 세로선이 보여요.
- 다른 묶음의 탭 줄에 놓으면 그 자리에 끼워 넣어요(`dropTab`의 `index`, `placeAt`).
- 프로젝트 탭은 항상 맨 앞이에요.

**탭이 많을 때**
- 탭은 이름을 줄여 가며 최소 88px까지 좁아져요(프로젝트 탭은 그대로).
- 그래도 넘치면 탭 줄 양끝에 ‹ › 화살표가 생겨 2/3 화면씩 넘겨요. 마우스 휠로도 옆으로 넘기고, 열린 탭은 항상 보이는 자리로 스크롤돼요.

**모양**
- 탭 줄은 28px로 얇고, 탭은 각진 모양이에요. 탭 사이는 세로 선으로 나눠요.
- 열린 탭은 위쪽에 2px 강조색 선이 있고, 바탕이 아래 화면과 같은 색이라 이어져 보여요.
- 다른 탭에 갔다 와도 저장 안 한 편집은 그대로예요(파일 편집기를 숨긴 채 살려 둬요).

**분할과 새 창**
- 탭 줄은 탭 묶음마다 하나예요. 분할, 탭 옮기기, 새 창은 → [분할 화면과 새 창](split-and-windows.md)

## 구현

**상태**(store.ts)
- `tabs: Record<프로젝트 루트, StageTab[]>`
  - `StageTab`은 `{ kind: "wt", path }` 또는 `{ kind: "file", base, rel, diff }`이고, 둘 다 `preview?`가 있어요.
- `withTab(tabs, root, tab, pin)`
  - 이미 있는 탭이면 자리를 그대로 두고, 이번에도 미리보기로 열 때만 미리보기로 남겨요.
  - 새 탭이면 `pin`일 때 끝에 붙이고, 아니면 기존 미리보기 탭 자리를 대신해요(없으면 끝에 붙여요).
- 탭을 여는 함수
  - `select(path, pin?)`: 워크트리로 가요. 편집기도 함께 내려요(`editor: null`). 프로젝트를 바꾸는 `setActive`, `addRepo`도 편집기를 내려요.
  - `openEditor(e, pin?)`: 파일을 열어요.
- `pinTab(tab)`: 미리보기를 고정해요. 부르는 곳은 세 군데예요.
  - `CodeView`: 편집이 생겼을 때
  - `Composer`(AgentNode.tsx): 보낸 뒤
  - `StageTabs`: 탭을 더블클릭할 때
  - App.tsx `.stage-body`: 화면 안을 더블클릭할 때
- 지금 화면의 탭은 저장하지 않고 `activeTab`으로 계산해요(열린 파일 → 고른 워크트리 → 프로젝트).
- `closeTab`: 화면의 탭을 닫으면 이웃 탭으로 한 번에 옮겨 가요. 그래서 중간 상태가 기록에 남지 않아요.
- `dirtyFiles`, `setFileDirty`: 저장 안 한 파일 목록이에요.

**뒤로/앞으로 기록**
- `nav: { list: Nav[], i }`. `Nav`는 `{ root, path, editor }`예요.
- `useStore.subscribe`가 위치가 바뀔 때마다 `i` 뒤를 잘라내고 새 위치를 붙여요. 같은 위치면 붙이지 않아서, 뒤로 가기 자체는 기록을 늘리지 않아요.
- `navTarget(s, dir)`는 갈 수 있는(`navValid`) 가장 가까운 기록을 찾아요. `goNav(dir)`는 그 위치를 그대로 되살리고, 탭이 없으면 미리보기로 다시 만들어요.

**화면**
- `StageTabs`: 왼쪽은 탭 목록(`.stage-tab-list`, 가로 스크롤), 오른쪽은 ‹ › (`.stage-nav`)예요.
- zustand v5는 셀렉터가 매번 새 객체나 배열을 돌려주면 끝없이 다시 그려요. 그래서 `editor`와 `selectedPath`를 따로 고르고, 빈 목록은 상수 `NO_TABS`를 써요.
- App.tsx는 모든 프로젝트의 파일 탭마다 `CodeView`를 띄우고, 화면의 것만 `active`예요.

## 제약과 알려진 문제

- 탭 목록과 뒤로/앞으로 기록은 앱을 다시 켜면 사라져요. 마지막 워크트리 탭 하나만 고정 탭으로 다시 생겨요.
- 탭을 끌어서 순서를 바꾸는 기능은 없어요.
- 마우스 뒤로/앞으로 버튼이나 단축키(Alt+←/→)는 아직 연결하지 않았어요.
- 화면에서 확인하지 않았어요.

## 결정 기록

- 탭 없이 화면이 그냥 바뀌니 어디서 왔는지 놓친다는 의견에서 탭을 넣었어요. 프로젝트·워크트리·파일을 한 줄에 쌓는 쪽을 골랐어요.
- 누를 때마다 새 탭이 생기는 게 번거롭다는 의견에, VS Code의 미리보기 탭 정책을 그대로 따랐어요.
- 탭은 처음의 둥근 34px 모양에서 얇고(28px) 각진 모양으로 바꿨어요.
